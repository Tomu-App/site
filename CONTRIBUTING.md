# Contributing

Thanks for considering a contribution to the **Tomu site**.

## Scope

This repo holds the marketing site at `tomu.foo` and the newsletter sign-up with double opt-in. It does not hold the app or the sync server (repo `Tomu-App/app`) or the specification (repo `Tomu-App/docs`).

## Layout

- `src/worker.ts`: Worker entry (SvelteKit plus the daily cron cleanup).
- `src/routes/`: pages and `api/subscribe`. Directory names are English; Paraglide localizes the public URLs.
- `src/lib/server/`: sign-up handler, subscriptions, tokens, mail, Turnstile, security headers, DB.
- `src/lib/content/`: legal texts as Markdown (German binding, English translation).
- `src/lib/components/`: UI components.
- `messages/`: all UI and mail text (`de.json`, `en.json`).
- `migrations/`: D1 migrations generated by Drizzle.
- `test/`: Vitest suites, run in the Workers runtime.

## Prerequisites

- **Node.js** in the version from `.node-version` and **pnpm** (version pinned in `package.json` `packageManager`).
- For local development, copy `.env.example` to `.env.local`. Do not create a plain `.env` or a `.dev.vars` (see `README.md`).

Run `pnpm install` once, then `pnpm lint`, `pnpm build`, `pnpm check` and `pnpm test` before you push. CI runs the same four.

`pnpm install` also installs two Git hooks (husky, `.husky/`):

- `commit-msg` rejects subjects that are not Conventional Commits (`<type>(<scope>)!: <description>`). Merge, revert and `fixup!` commits pass.
- `pre-push` runs the same four checks as CI only when the push updates `main`. Pushes to other branches skip it, since their PR runs CI. It checks the working tree, so stash uncommitted changes first. `git push --no-verify` skips both hooks in an emergency.

## What a good change looks like

- **Keep the changeset complete.** A change updates the affected docs (`README.md`, `CLAUDE.md`, `CHANGELOG.md`) in the same PR.
- **Format with Prettier.** `pnpm format` fixes what `pnpm lint` reports.
- **All user-facing text goes through Paraglide**, in both `messages/de.json` and `messages/en.json`. No hardcoded strings.
- **Schema changes** in `src/lib/server/db/schema.ts` come with the migration from `pnpm db:generate`, committed in `migrations/`.
- **After editing `wrangler.jsonc`**, run `pnpm gen` and commit `worker-configuration.d.ts`.
- **Privacy rules are not negotiable:**
  - no analytics, tracking or third-party scripts except Cloudflare Turnstile;
  - a sign-up never reveals whether an address is already registered;
  - never log email addresses, tokens or URLs containing tokens, and never store IP addresses;
  - confirm and unsubscribe act only on POST, never on GET.
- **Never commit `.env*` files** except `.env.example`.

## Pull requests

- Branch off `main`; PRs target `main`.
- **Conventional commits** (`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`).
- Describe what you changed and why, and confirm CI is green. The [PR template](.github/pull_request_template.md) has the sections.
- Add an entry under `[Unreleased]` in `CHANGELOG.md` for user-facing changes; the maintainer cuts releases.
- There are no preview deployments: test locally with `pnpm dev` or `pnpm preview`. Merging to `main` deploys to production.

## AI tools

AI tools are welcome - this repo is laid out for Claude (as can be seen in `CLAUDE.md`). You stay responsible for what you submit: read it, test it, and be able to explain it in review (also _why_ certain decisions have been made).

- **No `Co-Authored-By` trailers** (or similar AI footers) in commits. Remove the ones your tool adds.
- **Name the tool in the PR.** The last line of the PR description says which AI was used, for example `AI: Claude Code (Claude Opus 5.5)`, or `AI: none`. It is a note for reviewers, not a disclosure you have to justify.
